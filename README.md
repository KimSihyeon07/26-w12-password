# 비밀번호 보안 도구 (`26-w12-password`)

> 이 README는 실습을 완성한 뒤, 배포 직전 단계에서 직접 채워 넣습니다.
> 실습 안내와 완성 기준은 [`guide.md`](./guide.md)를 참고하세요.

## 소개

비밀번호 강도 점검, 안전한 비밀번호 생성, HIBP API 기반 유출 여부 확인, 그리고 AES-GCM 암호화 메모 기능까지 한곳에 담은 비밀번호 보안 도구입니다. 평문 비밀번호를 로그나 저장소에 남기지 않고 브라우저 내부에서 안전하게 처리하는 데 초점을 맞췄습니다.

## Vite 프로젝트 직접 구성 경험

1. 지난주처럼 미리 세팅된 템플릿을 받아서 바로 시작하는 게 아니라, 빈 저장소에서 `npm create vite@latest .`로 직접 프로젝트를 구성하면서 프로젝트 폴더 구조와 설정 파일, 빌드 흐름이 어떻게 연결되는지 더 직접적으로 체감할 수 있었습니다.
2. `create-vite` 실행 과정에서 기존 파일이 덮어씌워질 수 있다는 점을 보며 명령어 실행 전 파일 백업과 Git 상태 확인의 중요성을 느꼈습니다. `.gitignore`에는 `node_modules`, `dist`, 그리고 환경변수 파일(`.env`, `.env.*` 등)을 추가했는데, 불필요한 빌드 산출물이나 용량이 큰 의존성 폴더, 민감한 설정 파일이 원격 저장소에 올라가는 것을 막기 위해 필요합니다.

## 나의 AI 기획·구현 과정

1. AI와 대화하며 기능을 기획하고 구성한 뒤, Antigravity IDE에서 코드를 작성하고 터미널로 빌드·배포·Git 작업을 함께 진행했습니다.
2. 길이 조건과 문자 종류(대문자, 소문자, 숫자, 특수문자) 조합 다양성 등 보안상 중요한 요소를 중심으로 강도를 구분해 사용자가 직관적으로 약한 비밀번호를 피할 수 있도록 구성했습니다.
3. 구현과 Git/배포 과정에서 `.gitignore` 반영 순서나 브랜치(`dev`와 `main`) 구분, 배포 설정 등에서 헷갈리는 부분이 있었지만, 변경 사항과 브랜치를 하나씩 확인하고 빌드·배포 절차를 차례대로 밟아 해결했습니다.

## 보안 점검 (사이버보안과 체크포인트)

1. `Math.random()`은 예측 가능성이 있는 의사난수 생성기(PRNG)이기 때문에 보안이 필요한 비밀번호 생성에는 적합하지 않습니다. 반면 `crypto.getRandomValues()`는 암호학적으로 안전한 난수(CSPRNG)를 생성하므로 비밀번호처럼 추측되면 안 되는 값을 만들 때 사용해야 합니다.
2. 실제 요청 주소 예시: `https://api.pwnedpasswords.com/range/5BAA6`
   평문 비밀번호나 40자리 전체 SHA-1 해시는 서버로 전송되지 않고, 해시 값의 앞 5자리(prefix)만 요청 경로에 포함됩니다.
3. k-익명성 방식을 쓰더라도 서버는 요청이 들어온 시각·IP 주소 같은 접속 메타데이터와 함께, 사용자가 입력한 비밀번호 SHA-1 해시의 **앞 5자리 접두사**를 알 수 있습니다. 또한 해당 접두사를 가진 유출 해시 목록을 반환하므로, 응답 받은 목록에서 내 뒷부분 해시가 일치하는지 확인하는 과정이 뒤따릅니다.
